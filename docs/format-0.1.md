# TagMAKER interchange format 0.1

The JSON root is `{ "format": "tagmaker-project", "version": "0.1", "project": {...} }`. Only version `0.1` is accepted. [Example](../samples/example-project.json) is synthetic and intentionally refers to a video file not included in the repo. Import it through the opening dialog or `storage.interchange.import_json(path)`.

The suite-level [JSON Schema and VideoMAKER fixture](../../playmaker-schema/README.md) are maintained in the sibling `playmaker-schema` repository. The SQLite file is local autosave storage; JSON 0.1 is the cross-product contract.

`project` contains match identity, sport/profile/level, season, `teams` and `roster` arrays with stable string IDs, ordered `media`, `events`, manual clock state, shortcuts, an optional embedded `profile_data` snapshot, and last video position. A custom profile travels with the project. Each media item has `media_id`, relative `path` where the drives permit it, nullable `duration_ms`, and optional `size_bytes`. Clip order defines a **sequential** virtual timeline, not synchronized cameras. `global_video_time_ms` is the sum of all earlier clip durations plus `source_time_ms`. Clip durations are read from libmpv metadata, not by decoding all frames in Python. File relocation uses the JSON/SQLite directory as its path base. No media bytes are included.

Imported roster entries keep TagMAKER `id`, `team_id`, `name`, nullable integer `number`, `called_up` for the match, and `webmaker_player_id`, `webmaker_team_id`, `webmaker_season`, and `webmaker_competition` for repeat imports. Those WebMAKER source IDs are metadata; tagged events always reference the stable TagMAKER player ID. Older/manual entries without `called_up` are treated as selected.

Each event has `event_id`, `match_id`, `type`, `sport`, nullable `team_id`/`player_id`, `related_event_ids`, `source_media_id`, `source_time_ms`, `global_video_time_ms`, nullable `period`, nullable `game_clock_ms`, nullable `clock_direction` (`up`/`down`), `timestamp_quality`, nullable `points`, `note`, and an `attributes` object. Times are integer **milliseconds**, never seconds. Player timestamps are rounded to the nearest millisecond and tagged `player-reported-ms`; they are estimates of presented media time, especially with variable frame rate material. They are not frame indices. `game_clock_ms` may be null when no manual sync exists. `clock_sync` events record previous/new manual values in attributes. `score_snapshot` and `score_correction` store a `scores` map from team IDs to authoritative point totals. They are not scoring plays and are excluded from point aggregation.

CSV uses UTF-8 with BOM for Excel compatibility. Columns are `format_version,match_id,sport,team_id,player_id,event_type,count,observed_points`. Each row counts recorded events by team/player/type; empty IDs mean unspecified. This export is **not** a final match score feed. A consumer must process score corrections if it needs an authoritative scoreboard.

The SQLite database keeps one transactionally replaced project snapshot in `project(id=1,payload TEXT)` with WAL enabled. Media paths are relative to the database directory. This is an autosave format, not a published cross-product API. If interrupted during a save, SQLite retains the previous committed snapshot.
