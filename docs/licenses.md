# Licenses and distribution audit

TagMAKER source is GPL-3.0-or-later; see [LICENSE](../LICENSE). The implementation uses Python's standard library, PySide6 Essentials, `python-mpv`, PyYAML, and a user-provided libmpv binary.

| Component | License information | Distribution action |
| --- | --- | --- |
| TagMAKER | GPL-3.0-or-later | Include source and LICENSE. |
| Qt for Python / PySide6 Essentials | LGPLv3/GPLv3 or commercial options according to [Qt documentation](https://doc.qt.io/qtforpython-6/) | Preserve Qt notices and library replacement rights when redistributing binaries. |
| python-mpv | Source repository provides [LGPL and GPL license files](https://github.com/jaseg/python-mpv) | Verify the exact package release metadata and notices for a binary distribution. |
| PyYAML | The installed 6.0.3 package declares MIT in its package metadata. | Include the version's license notice when redistributing. |
| Python runtime | [PSF License Version 2](https://docs.python.org/3.12/license.html), with incorporated third-party components | Include matching Python license and applicable incorporated-component notices for a frozen build. |
| PyInstaller bootloader | [GPL-2.0-or-later with a bootloader exception](https://github.com/pyinstaller/pyinstaller/blob/develop/COPYING.txt) | Include the exact version's notices in the release audit. |
| Inno Setup compiler | [Inno Setup terms](https://jrsoftware.org/isinfo.php), with [commercial licensing guidance](https://jrsoftware.org/isorder.php) | Its license permits commercial use. The author requests, but does not strictly require, commercial users to buy a license. Keep its embedded copyright notices intact. |
| libmpv / mpv | [mpv Copyright](https://github.com/mpv-player/mpv/blob/master/Copyright) says GPLv2+ by default; LGPLv2.1+ is possible only for an audited build without GPL-only sources. `-Dgpl=false` alone is not a blanket license grant. ## Exact local test binary (25 October 2026)

The local test archive is the [shinchiro 2026-10-21 x86-64 development build](https://github.com/shinchiro/mpv-winbuild-cmake/releases/tag/20261021), archive SHA-256 `efc719eff3dc5954b4a5efc800632808bcec01cc9034940dd14e5eb7fe9ea633`. The extracted `libmpv-2.dll` SHA-256 is `04e4d27dc385dc18ddd93fbe69c75e635b864f3c6ec53a9122df54c2f7842f4a`. The archive contains the DLL, an import library, and headers; it does **not** contain license notices, component manifests, build configuration, or corresponding FFmpeg/mpv source. It is suitable for local testing, but these missing materials prevent a complete redistribution audit from the archive alone. The local Python packages are PySide6-Essentials 6.12.0, python-mpv 1.0.8, and PyYAML 6.0.3.

The [mpv copyright file](https://github.com/mpv-player/mpv/blob/master/Copyright) says mpv is GPLv2+ by default and only an audited GPL-free build can be LGPLv2.1+. [FFmpeg's legal page](https://ffmpeg.org/legal.html) says optional GPL parts can change FFmpeg's license and calls for matching source, build configuration, and notices for distribution. [Qt for Python](https://doc.qt.io/qtforpython-6/) lists LGPLv3/GPLv3 and commercial terms, plus [third-party notices](https://doc.qt.io/qtforpython-6/licenses.html). The GPL-3.0-or-later TagMAKER source does not by itself supply the missing notices and source for bundled binaries.

The repository does **not** track a DLL, FFmpeg, an installer, or a portable zip. A locally built, ignored private installer candidate may exist under `dist/`; it is marked `PRIVATE TEST BUILD` and is not a release artifact. Before public packaging, select a binary with clear licensing and build provenance; pin every version and hash; inspect linked components; include the applicable notices, license texts, and corresponding source access; then test the packaged application and library replacement where required. Until that audit is complete, a public installer must not bundle the local test DLL.

## Distribution audit of the private installer (27 October 2026)

**Decision: the current self-contained installer is not cleared for publication.** This is a provenance and source-delivery finding, not a claim that mpv and TagMAKER have incompatible open-source licenses. Do not upload `dist/TagMAKER-0.1.0-private-alpha-20261025-3.exe` as a public release asset.

The `libmpv-2.dll` SHA-256 above matches the upstream `mpv-dev-x86_64-20261021-git-e471496c56.7z` release asset. The [upstream release](https://github.com/shinchiro/mpv-winbuild-cmake/releases/tag/20261021) links to [workflow run 39518569492](https://github.com/shinchiro/mpv-winbuild-cmake/actions/runs/39518569492), which built from [builder commit `1f8d2e7`](https://github.com/shinchiro/mpv-winbuild-cmake/tree/1f8d2e76255abc48f0456d9be99b4cab9c6566e6). The archive names identify [mpv `e471496c56f0`](https://github.com/mpv-player/mpv/tree/e471496c56f0f49c133bd88b50aed62b845f1909) and [FFmpeg `9a861e9687d3`](https://github.com/FFmpeg/FFmpeg/tree/9a861e9687d30e657d59521817cad18405995983). The builder's [FFmpeg recipe](https://github.com/shinchiro/mpv-winbuild-cmake/blob/1f8d2e76255abc48f0456d9be99b4cab9c6566e6/packages/ffmpeg.cmake) explicitly enables GPL, version 3, x264 and x265. This points to a GPLv3 FFmpeg build under [FFmpeg's licensing notes](https://github.com/FFmpeg/FFmpeg/blob/9a861e9687d30e657d59521817cad18405995983/LICENSE.md). The [mpv copyright file at the same source revision](https://github.com/mpv-player/mpv/blob/e471496c56f0f49c133bd88b50aed62b845f1909/Copyright) says GPLv2-or-later is its default. These are compatible in principle with TagMAKER's GPLv3-or-later source.

The DLL is a large statically linked build. Its [build recipe](https://github.com/shinchiro/mpv-winbuild-cmake/blob/1f8d2e76255abc48f0456d9be99b4cab9c6566e6/packages/CMakeLists.txt) names many additional packages, including codecs, subtitle renderers, TLS and image libraries. The `mpv-dev` archive has a DLL, import library and headers but no complete component manifest, exact source revisions for those linked packages, their license notices, or a corresponding-source bundle. The workflow log records package updates but not a complete revision manifest. A current checkout of the builder would not identify the source versions actually linked on 21 October. [GPL guidance](https://www.gnu.org/licenses/gpl-faq.en.html#DistributeExtendedBinary) requires corresponding source for the actual binary; source for merely similar versions is insufficient. Without that source and notice set, this DLL cannot be passed as audited for redistribution.

The previous PyInstaller analysis also revealed unrelated DLLs selected through the developer machine's `PATH`: Poppler supplied ICU and OpenSSL, while libheif supplied Windows CRT copies. The first private installer included some of those files, and Poppler's incompatible ICU caused the reported QtCore startup failure. `packaging/build_windows.ps1` now limits `PATH` during PyInstaller analysis and `packaging/check_binary_provenance.py` rejects DLL sources outside the Python environment, base Python runtime, Windows, and the explicitly selected mpv DLL. A rebuilt **one-folder private test** passed that provenance check with 46 binary entries and starts with a `.tagmaker` project. The earlier installer remains a historical private test artifact; it has not been replaced with a publishable installer.

Other binary components still require release packaging work: the exact Python 3.12.14 runtime and its OpenSSL 3.5.8 DLLs, PySide6 Essentials and Shiboken6 6.12.0 (which offer a GPLv3 option), python-mpv 1.0.8, PyYAML 6.0.3, Qt's bundled third-party code, and the PyInstaller 6.22.3 bootloader. Their versions and upstream license routes are identifiable, but the current installer does not include a complete third-party notice set or a corresponding-source index. Those items must be supplied for the final binary, even if libmpv is removed from it.

One possible distributable alpha design omits `libmpv-2.dll` and asks users to supply a compatible DLL separately. That avoids redistributing the unmanifested mpv build in the TagMAKER installer, but changes the install and first-run experience. It still requires the remaining notice/source work and a clean Windows install/playback test. A self-contained installer instead needs a libmpv build with a verified component manifest, exact corresponding source and required notices, or a new controlled build that records them.

## External-libmpv installer candidate (27 October 2026)

The user accepted a separate libmpv download for the alpha. The default build now omits `libmpv-2.dll`, exposes **Configure libmpv** in the UI, and remembers the chosen path. A sanitized PyInstaller run passed 19 tests and verified all 44 native-binary source paths. The one-folder EXE started without a DLL in the bundle, and the source backend loaded the separately selected DLL. The Inno installer installed per-user, registered `.tagmaker`, launched, and uninstalled cleanly on the development account. Its installed folder contained no libmpv DLL.

The installer now contains `THIRD_PARTY_NOTICES.md` and the available license texts for CPython, OpenSSL, Qt, python-mpv, PyYAML, PyInstaller, and Inno Setup. This **private candidate is still not cleared for public upload**. The PySide6/Qt wheels contain many Qt DLLs and plugins but no wheel-specific SBOM or full third-party attribution set. [Qt's 6.12.0 attribution list](https://doc.qt.io/qt-6/licenses-used-in-qt.html) and [SBOM guidance](https://doc.qt.io/qt-6/sbom.html) identify the needed component notices; they need to be matched to the binaries actually in this wheel and included in the installed package. The exact PySide6/Shiboken6 wheel source/build correspondence also remains to be verified. The build uses Codex's bundled Python runtime; its provenance and embedded libffi notices have not been matched to a public redistribution package. The installer also contains Microsoft Visual C++ runtime DLLs from the Python/PySide environments; [Microsoft's redistribution guidance](https://learn.microsoft.com/cpp/windows/redistributing-visual-cpp-files) requires checking the applicable license and file list. The current source links are useful references, not evidence that these obligations are satisfied. A clean Windows account and packaged MP4/MTS playback with a user-selected DLL are still untested. Keep the private marker and do not create a public release until these gates close.
